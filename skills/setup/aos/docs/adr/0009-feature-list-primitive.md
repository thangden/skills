# 0009 — Feature work-units live in .claude/features/, outside Memory; the harness flips `passing`, never the implementing agent

aos tracked knowledge (Memory, four Anthropic types, ADR-0002) and mutable sprint state (the Tracker, ADR-0002) but had no primitive for a unit of deliverable work. Harness-engineering treats the feature list as the spine of the harness — the scheduler picks the next unit, the verifier gates its transitions, the reporter hands it off — and each unit carries a behavior, a deterministic verification, a state, and evidence. Without it, "what is done and how we know" lives only in prose, and agents self-certify completion.

A feature is work-unit STATE, not knowledge, so it does NOT go into Memory — that would either break the four-type rule of ADR-0002 or let Janitor scan a work-unit as if it were a durable fact. Nor does it belong in the Tracker, which is free-form sprint narrative. aos v2.1 introduces a dedicated primitive: `.claude/features/<slug>.md`, committed (team-shared), one file per feature. `templates/features/feature-template.md` defines the shape — frontmatter `state` (not_started | active | blocked | passing) and `depends_on`; a single demoable `Behavior`; deterministic `Verification` checks; a weighted `Definition of Done` rubric; and an `Evidence` block recorded as work lands.

Completion is decided by the harness, not the implementing agent. `templates/skills/feature-evaluator.md` (a Skill, `model: haiku`, read-only tools) runs the Verification checks and the DoD rubric, computes a 0–100 score, and recommends a state — but recommends `passing` only when the score is 100 and every Verification check passes. It proposes; a human or an orchestrator writes the state. This is the planner/generator/evaluator separation: the context that implemented the work is not the context that grades it, which removes the calibration drift that makes self-evaluation systematically optimistic. Once `passing`, a feature must not silently revert.

Alternatives considered: a fifth Memory type `feature` (rejected — breaks ADR-0002's four-type contract and pollutes Janitor's knowledge scans); structuring the Tracker into a feature list (rejected — overloads one free-form file, gives no per-feature query, and Janitor deliberately does not scan the Tracker); letting the implementing agent mark its own features done (rejected — the exact failure mode harness-engineering warns against). Cross-repo feature coordination and an automatic Stop-hook evaluator pass are deferred to the cross-repo orchestrator phase (scope C).
