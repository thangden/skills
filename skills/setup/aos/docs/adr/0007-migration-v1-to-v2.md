# 0007 — Migration v1 → v2 is explicit, with a backup folder for rollback

aos v2 changes the on-disk layout significantly. Memory shifts from three fixed buckets to one Entry per file under the 4-type schema (ADR-0002). The tracker moves out of `.claude/memory/`. Hooks are replaced (ADR-0005). Curator and Janitor skills are added (ADR-0003, ADR-0004). A version marker, `.claude/aos-version`, is introduced. Existing v1 workspaces can't use v2 features without transformation.

Migration is invoked explicitly via `/aos --upgrade`. aos doesn't auto-prompt when `/aos` runs in its normal mode — Phase 0's detection gate handles new-vs-existing, but it surfaces upgrade as a suggestion rather than acting on it. Rollback is provided via a backup folder at `.claude/_v1-backup-YYYYMMDD/` created before any transformation. `/aos --rollback` restores from that backup.

Auto-detection plus prompt-on-regular-`/aos` was rejected because cloned workspaces often carry partial v1 shape — running `/aos` to bootstrap a fresh project would trigger an upgrade the user didn't want. The explicit flag makes intent unambiguous. One extra word costs little in the rare case where upgrade is genuinely desired, and rules out the false-positive class.

A backup folder is the rollback mechanism because it works without git (Non-Tech users frequently don't initialize git), it's atomic, and it's human-inspectable — the user can diff the backup against the current state. The disk cost is negligible since Memory totals a few MB at most. Side-by-side parallel layouts were rejected because Janitor would scan both, surface false conflicts, and confuse users about which is live. Git stash was rejected because too many users skip `git init`, leaving stash with no place to land.

The migration runs in this order. Pre-check that `.claude/` exists and `.claude/aos-version` is absent — abort otherwise. Create the backup. Split `.claude/memory/system-knowledge.md` by H2 headings, writing each as an Entry via Curator's interview-mode (one `type: project`, `scope: team` Entry per heading; on parse failure, fall back to one `legacy-system-knowledge` Entry and log a warning). Move `.claude/memory/active-context.md` to `.claude/active-context.md`. Reformat episodic files with frontmatter, flatten the subfolder. Generate the `MEMORY.md` index. Install Curator and Janitor from templates, moving v1's `memory-curator.md` and `memory-janitor.md` to `.claude/skills/_v1-deprecated/`. Replace `quality-gate.sh` with the new hook scripts, moving the v1 hook to `_v1-deprecated/`. Replace `settings.json`, preserving any user customizations beyond hook registration. Append a Memory Layer marker block (`<!-- aos-v2:start --> ... <!-- aos-v2:end -->`) to CLAUDE.md. Write `.claude/aos-version`. Append the day's episodic log.

Rollback follows a move-then-restore pattern, because the backup folder sits inside `.claude/`: move the backup to a sibling temp path, remove `.claude/` entirely, then move the backup back as the new `.claude/`. A naive `rm -rf .claude/* && cp -r` would delete the backup before reading it. Rollback also reverses the root-file changes — sed-removing the marker block from CLAUDE.md, and removing aos v2 patterns from `.gitignore` (or deleting `.gitignore` entirely if it didn't exist before migration).

`.claude/_v1-backup-*/` is a reserved directory pattern — aos must add it to the workspace `.gitignore`, and Janitor excludes it from scans. Migration is non-idempotent by design; the aos-version precheck prevents accidental double-run. The H2-split fallback can produce a single legacy Entry that's large, but Janitor's full scan will flag it for splitting — that's correct behavior, surfacing cleanup work to the user.
