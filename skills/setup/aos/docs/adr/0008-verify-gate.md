# 0008 — Stop runs a language-agnostic, configurable code-verify gate; block is the default for Tech repos

aos v2.0 shipped only a memory-schema hard-block (ADR-0005); code verification was left to each workspace to hand-roll. In practice the franchise-portal workspace grew its own `quality-gate.sh` hard-wired to `npx tsc` and TanStack `_auth/` RBAC scanning — useful, but not portable to a Go or Python repo, and not something aos itself provided. Harness-engineering names this gap directly: an agent that self-grades "done" without a machine-checkable gate declares victory early, and a unit-only gate misses system-level failures. aos needs to SHIP the gate, and it needs to be language-agnostic.

aos v2.1 ships `templates/hooks/verify-gate.sh` plus `templates/hooks/config.env`, wired on the Stop hook alongside `memory-stop.sh`. The gate reads every command from `config.env` — `COMPILE_CMD`, `LINT_CMD`, `TEST_CMD`, `E2E_CMD` — so the same bash script verifies a TS repo (`tsc`, `vitest`), a Go repo (`go build`, `go test`), or a Python repo (`mypy`, `pytest`) with zero language assumptions in the script. Phase 2 Layer 4 detects the stack from `package.json` / `go.mod` / `pyproject.toml` and fills the commands; an empty command means that layer is skipped, and aos never invents a command the repo does not have.

The gate runs three layers in order — L1 compile/static, L2 unit/integration, L3 E2E — matching the testing-adequacy gradient. L3 is opt-in per turn (`E2E_ON_STOP`, default 0) because end-to-end suites are too slow to run on every Stop; they belong in CI or manual runs. On any failure the gate prints a "teacher's red pen" message: which layer failed, the exact command, and the last 20 lines of output, so the next step is the fix rather than a guess.

`VERIFY_GATE_MODE` chooses the consequence: `block` exits 2 and stops the turn, `warn` surfaces the failure to stderr without blocking, `off` skips entirely. Default is `block` for Tech repos and `off` for Non-Tech — a deliberate, narrow extension of ADR-0005's "warn-only except schema" stance: code that does not compile or whose tests fail is the same class of state-corruption that justified the schema hard-block, so blocking is correct, but every team can downgrade to `warn` with one line. The mode is a config value, retunable without an ADR.

Alternatives considered: keeping verification per-workspace (rejected — every repo re-invents it, and aos cannot claim to be a harness while shipping no Feedback layer); a single non-configurable mode (rejected — Tech and Non-Tech have opposite defaults, and forcing block on a content team breaks flow); hard-killing on `VERIFY_TIMEOUT` (deferred — portable timeout enforcement differs across macOS/Linux; for C-narrow the value is advisory and documented, with `gtimeout`/`timeout` wrapping left to C-broad).
